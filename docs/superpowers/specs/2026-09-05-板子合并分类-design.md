## 1. 背景与目标

`板子/` 目录下有两类模板资产:

- **旧板子**: `banzi_南京邀请赛版.md`(1724 行,单一合并文档,带目录/页码/章节体例)
- **新板子**: 若干独立 md/cpp 文件(矩阵快速幂、多源bfs、多源djs、三色dfs、拓扑排序、floyd、树状数组理解、向上取整等),部分为空文件、部分含代码 bug

**目标**: 合并新旧板子 → 按「问题驱动」分类树重组到新建 `板子合集/` 目录 → 最小化矫正(仅修 bug/错位/笔误)→ 生成带双检索目录的 Typst 总文档 `banzi_ICPC网络赛版.typ` → `typst compile` 生成 PDF(页码自动、无需人工标记)。

## 2. 全局约束(不可违反)

1. **原文件零改动**: `板子/` 下所有旧文件(含 PDF、图例.png、.exe)一律不动,防止丢失。
2. **不写占位**: 当前没有内容的算法(二分、朴素Dijkstra、Bellman-Ford、SPFA、链式前向星、Tarjan、树形DP、虚树、Trie、广义矩阵乘、组合数、破环成链、背包/区间DP)不建文件、不建空分支;写好后再归位。例外: 用户点名新增的「线性筛因数」由本计划新写(标准最小版本)。
3. **问题驱动分类**: 文件夹名 = 问题描述,文件名 = 算法名。查找路径 = 思考路径。
4. **多用途算法复制**: 一个算法解决多类问题时,在多个问题目录下各放一份(当前: BFS →「无权或0-1边权最短路」+「图的遍历」;拓扑排序 →「环问题」+「为DP提供计算顺序」)。总文档正文只放一次,目录二多处出现同指一页(同一 label,页码自动一致)。
5. **语言与代码非必要不更改**: 保留作者原有讲解措辞、代码缩进、变量命名、宏、头文件、数据类型习惯。只做三类必要修改: ①§6 已确认的 bug 修复;②错位/笔误;③每个文件顶部补 3 行元信息(所属分类/复杂度/适用问题)。不做统一缩进、不统一 include、不做 int→i64 等风格改造。
6. **树的直径**仅保留用户已写的 3 行提纲,不补代码。
7. Bug 修正范围严格限定为 §6 清单(13 项)。

## 5. 合并总文档 — Typst + 双检索目录(v3 核心变更)

`板子合集/banzi_ICPC网络赛版.typ`,由 `typst compile` 生成 PDF:

1. **封面**(沿用旧版体例)
2. **目录一 · 算法直查表**: 按分类分组,`算法名 ..... 页码`。页码 = `#counter(page).at(<alg-xxx>)` **自动计算**,无需人工标记
3. **目录二 · 问题索引树**: 分类树缩进,叶结点 `算法名 ..... 页码`(同样自动);多用途算法(BFS/拓扑排序)引用同一 label,两处页码自动一致
4. **正文**: 按分类树分章,每个算法一个小节 `=== <alg-xxx> 算法名`;节内容 = 对应文件夹 md 的完整内容(文字照搬,代码原样入代码块)

技术要点:
- 页码自动: 每个算法标题带 label,`counter(page).at(<label>)` 返回真实页码;目录与正文天然一致,无需 PDF 后校正
- 中文字体: `#set text(font: ("New Computer Modern", "Microsoft YaHei"))`(Windows 自带,编译本地完成)
- 数学公式: LaTeX 语法最小转换为 Typst 原生 math(如 `$\mathcal{O}(n)$` → `$cal(O)(n)$`),语义等价;多行推导(aligned)拆为逐行公式
- 旧板子图片(含 OI-wiki 外链)全部弃用(链接已失效/需联网),与 v2 一致
